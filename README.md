# Zero-Trust Policy Enforcement for a Raft Cluster on the SEED Internet Emulator

A 4-node pysyncobj (Raft) cluster in AS166 on the SEED Internet Emulator, protected by
three ABAC policies (py-abac) that are enforced in the kernel and on live Raft messages.
node004 is a cluster member that turns malicious; once detected it is isolated from every
node and from the router.

## Network

| Host | IP | Role |
|---|---|---|
| ca_node | 10.166.0.71 | Certificate authority (Flask) |
| node001-003 | 10.166.0.72-74 | Trusted Raft members |
| node004 | 10.166.0.75 | Untrusted Raft member (turns malicious) |
| router0 | 10.166.0.254 / IX100 10.100.0.x | AS166 router, runs its own guard |

## The three policies (`abac_policies.json`, generated by `build_policies.py`)

1. **IP range** - only cluster -> cluster/services traffic is allowed (default deny). The IX
   range 10.100.0.0/24 and unassigned addresses in 10.166.0.0/24 are blackholed on every node.
2. **Time window** - untrusted nodes (node004, anything unregistered) may talk only between
   08:00 and 17:00. node001-003 are not affected.
3. **Malicious node** - any sender with a strike score of 3 or more is denied and isolated.
   Signals: invalid identity (+3: unregistered id or missing/expired/invalid certificate),
   message flood (+1 per message above the flood limit), unauthorised access (+3: connection to
   the decoy port 9999 on a core node), internet-access attempt (+3: seen by the router).

## Enforcement

- `enforce_ip_policy.py` - evaluates the policies every 2 s and applies blackhole routes plus
  iptables rules (both directions) on every node. Listens for signed quarantine notices (UDP 9998)
  and runs the decoy port (TCP 9999) on the core nodes.
- `raft_guard.py` - wraps the pysyncobj transport callback and evaluates every Raft message.
- `router_guard.py` - runs on the router: counts packets from cluster nodes towards 10.100.0.0/24,
  accepts notices, and drops all traffic from/to a quarantined address (including to the router).
- `zt_common.py` - quarantine list, HMAC-signed notices, iptables helpers.
- `ip_governance.py` + `ip_registry.json` - IP registry, range blocks, drift audit.
- `attack_node4.py` - turns node004 malicious (`flood`, `identity`, `probe`, `internet`, `all`, `stop`).

## Build and run

```bash
cd examples
source development.env
python3 build1_cryptobj.py
cd output
docker compose build $(docker compose config --services | grep -E '^[0-9a-f]{32}$')
docker compose build
docker compose up -d
```

## Tests

Offline: `python3 enforce_ip_policy.py selftest` (23), `python3 raft_guard.py selftest` (16),
`python3 ip_governance.py selftest` (10).

Live (needs the running network): `bash experiments/scripts/test_three_policies.sh ip|time|attack|reset`.
After an attack run `reset` and wait about 70 s before the next one (strike counts decay in 60 s).

Observed live: IP range audit OK on all nodes; node004 cut off at hour 22 and restored afterwards;
decoy-port probe, message flood and internet attempt each isolated node004 on node001-003 and the
router while the cluster kept running. Throughput with four nodes was about 198 counter units/s
(3-node baseline 183.9).

## Fault-injection experiments

`experiments/` holds the earlier leader/follower isolation runs (`data/`, `scripts/scenario.sh`,
`scripts/analyze.py`): leader isolated n=4, follower isolated n=3, 60 s isolation, 40 s heal.

## Limitations

- Notices are signed with the shared Raft password; a fully compromised core node could forge them.
- A rogue read-only member is dropped and logged but has no IP in the Raft transport, so it cannot be isolated.
- The flood limit (3000 messages / 10 s per sender, `/app/flood_limit`) is tuned to this lab.
- Certificates are checked for presence and validity dates, not against the CA signature.
- Quarantine is permanent until released (`python3 enforce_ip_policy.py release IP`).
